# Wallpaper Engine feature compatibility

## Purpose

This is a living parity contract, not a marketing checklist. Each capability
gets a stable ID used by renderer manifests, the compatibility database, UI,
fixtures, and automated tests.

Status values:

- `Target P0` — required for the first useful release.
- `Target P1` — required for a polished 1.0 release.
- `P2` — desirable after 1.0.
- `Backend-dependent` — expose honest per-renderer support.
- `Deferred` — recognized but not scheduled for 1.0.
- `Unsupported` — intentionally excluded for security, licensing, or platform
  reasons.

Official references confirm configurable user properties, audio buffers,
cursor events, media integration, playlists/profiles, runtime controls, and
performance policies:

- <https://docs.wallpaperengine.io/en/web/customization/properties.html>
- <https://docs.wallpaperengine.io/en/scene/scenescript/reference/class/IEngine.html>
- <https://docs.wallpaperengine.io/scene/scenescript/tutorial/cursor>
- <https://docs.wallpaperengine.io/en/web/audio/media.html>
- <https://help.wallpaperengine.io/en/functionality/cli.html>
- <https://help.wallpaperengine.io/en/functionality/wallpaperperapp.html>

Still deferred, not attempted this slice: stacked multi-effect compositing and `_rt_FullFrameBuffer`'s paint order (unchanged from S4). **Also new in S4b**: four of the S4a-era `compile_failed` bundled-shader root causes are fixed (`crates/kwe-scene-renderer/src/shaderpre.rs` only, no material-pipeline or Vulkan-layer changes) — see `docs/SCENE_FORMAT_V1.md` "`compile_failed` root causes fixed (S4b)" for the full technical account of each. (1) `#include` placement: this module's own documented deviation from upstream ("every `#include` sits above any function definition, so inlining in place is equivalent") was false for `shine_gaussian.frag`/`godrays_gaussian.frag`/`blur_precise_gaussian.frag`, which all `#include "common_blur.h"` as their FIRST line, before the `uniform sampler2D g_Texture0;` its functions read — fixed to splice every `#include`'s resolved text in just before `main(`, matching upstream's real `ShaderUnit::preprocessIncludes` placement. (2) `g_Point<N>` type narrowing: `effects/perspective.vert` (used by most of the corpus's effect chains) declares `g_Point0..3` as `vec2`, but the shared UBO slot is `vec4` — folding to the bare vec4 broke `squareToQuad`'s own call-site type (`'squareToQuad'`/`'inverse' : no matching overloaded function found`); fixed with a narrowing swizzle matching the shader's own declared type. (3) Array uniforms (e.g. `uniform float g_AudioSpectrum16Left[16];`, an audio-visualizer material) fell through every folding path and left a loose (non-block) uniform declaration in the compiled text — Vulkan's GLSL profile rejects that (`'non-opaque uniforms outside a block'`); fixed with a bounded (`MAX_ZERO_ARRAY_LEN` 1024) zero-initialized array replacement. (4) `max()` argument order: `#define max(x, y) max(y, x)` is upstream's own header macro, previously dropped on a mistaken "GLSL already matches HLSL" assumption — `max(0, someVec3)` (the real corpus shape, `nitro.frag`) has no matching GLSL overload unswapped; restored verbatim. ## How parity is proven

Every capability moves from planned to implemented only when it has:

1. a renderer or service capability-manifest entry;
2. an original synthetic fixture that exercises success and failure behavior;
3. automated protocol/state tests and, for rendering, an image/event oracle;
4. a UI presentation for supported, partial, unavailable, and failed states;
5. backend/version/hardware evidence recorded in the compatibility database;
6. documentation of intentional semantic differences from Wallpaper Engine.

Unknown fields and callbacks must be logged at a bounded rate and preserved
where possible. They must not crash a renderer or be silently presented as
supported.
