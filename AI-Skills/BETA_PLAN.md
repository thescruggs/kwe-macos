- 2026-08-23 — **S4b (scene port, `compile_failed` shader-preprocessor fixes) implemented** on `beta-s4b-particles` (same branch/slice as the particle-file entry below; priority item 4 of 4, done after item 1). Traced the S4a change-log's 13 pkg-bundled `compile_failed` shaders to their actual root causes (not just their `shaderc` error text) and fixed four distinct bugs, all in `crates/kwe-scene-renderer/src/shaderpre.rs`, none touching the material pipeline or Vulkan layer. (1) **`#include` placement** (`resolve_includes`): this module inlined an `#include`'s resolved text at its EXACT source position, on the documented (but false) premise that every `#include` in the corpus sits at file scope above any function definition — `shine_gaussian.frag`/`godrays_gaussian.frag`/`blur_precise_gaussian.frag` all `#include "common_blur.h"` as their FIRST line, before the `uniform sampler2D g_Texture0;` its `blur13`/`blur7`/`blur3` functions read; in-place inlining put those functions textually ahead of the declaration (`'g_Texture0' : undeclared identifier`). Fixed to match upstream's real `ShaderUnit::preprocessIncludes` behavior: every `#include`'s resolved text is now collected into one accumulator (flattened across nesting, encounter order) and spliced in just before the file's own `main(` definition. (2) **`g_Point<N>` type narrowing** (`standard_uniform_expr`): the shared `MaterialUniforms` UBO backs `g_Point<N>` with a `vec4` slot, but `effects/perspective.vert` (used by most of the local corpus's effect chains, via `common_perspective.h`'s `squareToQuad`) declares it locally as `uniform vec2 g_Point0;` — folding to the bare `vec4` expression changed the call-site TYPE, so `shaderc` reported `'squareToQuad'`/`'inverse' : no matching overloaded function found` for a function that exists, cascading into a `'=' : cannot convert from const float to 3x3 matrix` on the same line. Fixed with a narrowing swizzle (`.xy`/`.xyz`, matching the shader's OWN declared type from the same `parse_decl` call that already reads it) — a `vec4`-declaring shader (the common case) is byte-identical to pre-fix output. (3) **Array uniforms left as loose declarations** (`fold_declarations`): an array-typed uniform (`uniform float g_AudioSpectrum16Left[16];`, an audio-visualizer material's spectrum-band uniform this renderer does not feed live data into) was explicitly excluded from every folding path (`!name.contains('[')` guards all three) and fell through to the generic per-line pass-through, leaving the ORIGINAL loose `uniform TYPE NAME[N];` line in the compiled text — Vulkan's GLSL profile requires every non-opaque uniform to live inside a named block (`'non-opaque uniforms outside a block'`). Fixed: a recognized-element-type array now gets the same "still compiles, just inert" zero-default treatment as a scalar/vector uniform, as a NON-`uniform` explicitly zero-initialized array (`TYPE NAME[N] = TYPE[N](zero, zero, ...)`, GLSL has no broadcast shorthand for array initializers). Bounded at `MAX_ZERO_ARRAY_LEN` (1024 elements, generous over the local corpus's largest real array, 64) — past that bound, left on the pre-existing pass-through path rather than building an unbounded initializer-list string. (4) **`max()` argument order** (`SHADER_HEADER`): `#define max(x, y) max(y, x)` is upstream's OWN header macro (`ShaderUnit.cpp`), dropped from this module's port on the theory that GLSL already defines `max` the same way HLSL does — that theory missed the actual corpus shape: HLSL's `max(scalar, vecN)` broadcasts the scalar regardless of position, but GLSL's overload set only has `genType max(genType x, float y)` — the scalar must be SECOND, and even a bare integer literal like the `0` in `max(0, albedo.rgb)` (`workshop/2423477561/effects/nitro.frag`, `workshop/2988515046/effects/nitro.frag`, both pkg-bundled) needs GLSL's int -> float implicit conversion on that second-position argument to resolve at all — unswapped, neither argument order matches any overload (`'max' : no matching overloaded function found`). Restored upstream's macro verbatim; safe as a blanket swap because `max` is mathematically commutative for any call that already resolves — swapping only changes argument ORDER in the generated text, never the computed value, and the corpus sweep below found no scene where the un-swapped order was load-bearing. **Headline metric**: 60-package local corpus, `--assets-dir` configured, llvmpipe, 960x540, a 6 s/scene render budget (before/after built from the same `beta-b4-apply-quarantine` HEAD `360b986` baseline as the particle-file entry below; NOT directly comparable to the S3/S4 change-log's 2 s/scene figures, only to each other under identical conditions): candidate compiled 189 material layers through their real shader vs. 183 baseline, fallback dropped from 30 to 24, and `compile_failed` specifically dropped from 10 to 4 — four scenes each lost 1-2 `compile_failed` shaders (`2370927443`: 2→0, `2468489223`: 1→0, `2685383861`: 1→0, `3189982144`: 2→0) and ZERO scenes gained one (no regression across the whole 60-scene sweep). Two scenes that previously timed out within the budget now publish a frame (`2584025717`, `3775489189`) — plausibly this fix's effect, not independently isolated from timing jitter. Directly confirmed by name via a targeted reproduction (`materialshader::compile_stage` against each bundled pkg shader's real preprocessed text): `shine_gaussian.frag`, `godrays_gaussian.frag`, `blur_precise_gaussian.frag`, `perspective.vert`, `workshop/2084198056/effects/Simple_Audio_Bars.frag`, and `workshop/2423477561/effects/nitro.frag` all go from a compile error to `COMPILE OK`. New unit tests for each fix plus bounds/hostile-input siblings (`include_content_lands_before_main_not_at_its_own_line_position`, `include_with_no_main_appends_at_the_end_instead_of_dropping`, `main_like_identifiers_do_not_confuse_the_insertion_point_search`, `point_uniform_narrows_to_the_shaders_own_declared_type`, `point_uniform_declared_as_vec4_is_unswizzled`, `array_uniform_zero_fills_instead_of_leaving_a_loose_declaration`, `array_uniform_past_the_zero_fill_bound_is_left_unsupported_not_expanded`, `max_macro_swaps_arguments_matching_upstreams_header`) — 292 kwe-scene-renderer tests green (up from 284), full workspace suite green, `scripts/smoke-scene.sh` fully green (78 cases — unaffected, since it uses synthetic fixtures, confirming no regression to the existing pipeline), zero crashes across the corpus sweep. Gates: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` (all green). Widened the material pipeline's vertex format from exactly `a_Position`+`a_TexCoord` to any subset of six known attribute names (`a_Position`/`a_PositionVec4`, `a_TexCoord`/`a_TexCoordVec4`, `a_Normal` — always `+Z`, the quad is flat — `a_Color` — always opaque white), the `genericimage3`/`genericimage4`-family shape the S2/S3 docs' own survey flagged as a real, scoped follow-up. ## Key design decisions (verified against code)

- **D1 — JS engine: QuickJS(-ng) via `rquickjs` (MIT).** ES2023 level, has `JS_SetMemoryLimit`, interrupt handler (step budget), small footprint. Boa too slow for 60fps `update()`; Duktape too old; V8 too heavy. Execution contract: 64 MiB heap cap, 8 ms soft / 33 ms hard budget per `update()`; script exceptions log at bounded rate and keep last state — never kill the renderer.
- **D2 — Shaders:** internal passes GLSL→SPIR-V at build time (glslang, precompiled bytes in crate); wallpaper-provided shaders compiled at runtime via `naga` GLSL subset, fail-closed to default material, manifest `scene3d.shaders=subset`.
- **D3 — Video: libmpv linked into `kwe-video-renderer`** (LGPL-2.1+ dynamic, separate-process worker), `MPV_RENDER_API_TYPE_SW` render API (no EGL), `--hwdec=auto-safe` with one documented software retry. Keepalive re-publish loop so paused video never trips frame-timeout.
- **D4 — Web: `--remote-debugging-pipe` over a socketpair** (sandbox has `--unshare-net`; a debug *port* would be unreachable). `Page.startScreencast` JPEG → decode (image crate) → BGRA publish; **must ack `Page.screencastFrameAck`** or capture stalls. Pointer via `Input.dispatchMouseEvent` (real CSS :hover/:active); audio via `Runtime.evaluate` of the WE `audio_web` callback (128 floats, ≤30/s). Chromium flags add `--no-sandbox` (bwrap is the sandbox), `--disable-dev-shm-usage`, `--disable-gpu`, `--headless=new`. One-day CDP framing spike first; port+`DevToolsActivePort` bind is the fallback.
- **D5 — Audio worker: separate `kwe-audio-worker`** spawned by the daemon; captures via `pw-record --raw` (resolved once through bounded `pw-dump`), reuses `kwe_core::audio::analyze_stereo` (audio.rs:10-27), pushes 64-band frames over a socket; daemon forwards to active renderer latest-wins (pointer pattern, supervisor.rs:817-823). Opt-in: `--audio-capture` + per-wallpaper audio grant; teardown immediate on stop.
- **D6 — Renderer contract generalization:** `StartSpec` (supervisor.rs:114-123) gains `kind: RendererKind` + `content: ContentSpec` (Video{path}/Web{root}/Scene{path}); per-kind renderer paths, timeouts, resource limits, and env allowlist in `SupervisorConfig`; argv adds `--content <path>`; stderr piped into a bounded ring surfaced in `renderer.status`.
